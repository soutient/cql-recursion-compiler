# CQL recursion compiler 

This project models a foundational relational subset of Categorical Query Language (CQL). Tables are treated as objects, and foreign keys/join predicates act as morphisms (arrows). Query composition represents walking a path of morphisms across schema structures. The engine focuses on evaluating and eliminating identity morphisms (zero-length steps) before generating physical target strings. CQL (formerly AQL) was developed by Statebox in collaboration with Conexus AI Inc. The prototype is conceptually linked to the prospect of integration perspective of the Categorical Query Language (CQL), in which schemas, data transformations, and migrations are described using categorical and algebraic structures. In the present prototype, this relationship is made operational through a smaller recursive query language: categorical or algebraic query structure is represented explicitly in Haskell, while SQL serves as the concrete relational target language. Thus, the prototype should be understood not as a full implementation of CQL, but as a categorical intermediate representation whose relational operations are compiled into SQL. In other words, it represents relational computations as compositional syntax rather than as unstructured SQL text.

 ## Description
The main idea is to represent a recursive structure using `Fix`, and to combine the traversal into `hylomorphism`: `unfold` plus `fold` without explicitly creating an intermediate tree. This role of `Fix` and `hylo` corresponds to the standard recursion schemes in Haskell.

For real-world scaling, this project draws structural inspiration from [spell-music/data-fix](https://github.com/spell-music/data-fix), an ecosystem demonstrating how fixpoint types provide fold and unfold operations entirely for free once an AST is successfully defined as a fixed-point functor.

`cql-recursion-compiler` completely bypasses intermediate heap allocations using a categorical **hylomorphism (`hylo`)**. By joining an optimizing coalgebra (`optimizeCoalg`) with a text-generating algebra (`sqlAlgebra`), the optimization and compilation steps are fused at the machine-code level by GHC via short-cut **deforestation**, the structure exists conceptually, but its creation and subsequent destruction are combined into a single pass.

The mechanism by which composition occurs in hylo-morphism consists of the recursive interleaving of expansion and contraction steps at every level of the data structure. Instead of a sequential call—where `ana` first constructs the entire tree in memory and `cata` then destroys it—`hylo` computes them simultaneously. In Haskell, this is achieved through three key factors: the formulation of the `hylo` function itself, lazy evaluation, and compiler optimization **deforestation**.

For CQL hylo turns into a tail-recursive pipeline transformer. The "unfolding" step checks if a node is an optimal target (like discarding 1=1), and the "collapsing" step takes the cleared node and routes its nested sub-trees back into the same loop. The categorical abstraction completely flattens out into basic, optimal procedural logic. Recursion happens immediately inside the string builder. Notice that intermediate 'Fix' nodes are entirely bypassed.

The exact runtime execution function generated by this composition looks like a unified pattern-matching pipeline. It steps down the AST, applies the optimization rules, immediately invokes the recursive compilation, and stitches together strings without allocating.

As a result, **the theoretical "optimized intermediate AST" never exists in memory**. The raw AST structure is consumed linearly, optimized on the stack, and directly streamed into the target SQL string output, eliminating Garbage Collector (GC) pressure entirely during query compilation.
